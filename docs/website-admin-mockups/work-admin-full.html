두 가지 원칙

1. 같은 내용을 두 번 치게 하지 않는다.
한 번 넣은 정보가 여러 곳에 쓰이면 칸을 늘리지 말고, 그 칸 아래에 「쓰이는 곳」을 적습니다. 예외가 필요할 때만(검색 설명이 80자를 넘는 등) 그 자리에 조용히 안내가 뜨고, 누르면 그때 별도 값이 생깁니다.

2. 어드민은 화면을 흉내내지 않는다.
미리보기는 실제 홈페이지 화면을 불러옵니다. 어드민이 따로 스타일을 들고 있으면 시간이 지나면서 반드시 어긋납니다.

전체 설계 요약

탭 4개. 기본정보 · 본문 · FAQ · 연결. 탭 옆 점으로 진행 상황을 보여주고, 목록 화면에도 같은 점이 나옵니다.

검색 정보 탭을 통째로 없앴습니다. 같은 내용을 두 번 치게 하는 칸이었습니다. 검색 제목은 제목을, 검색 설명은 한 줄 요약을, 공유 이미지는 대표 이미지를, 검색 키워드는 태그를 그대로 씁니다. 검색 때문에 새로 칠 것은 하나도 없습니다.

블록은 자유롭게 쌓습니다. 제목 + 기본 설명(고정 위치)까지는 모든 블록이 같고, 그 아래는 자유 편집입니다. 순서가 앵커 메뉴 순서입니다.

에디터는 구조만 다룹니다. 문단 · 소제목 · 굵게 · 링크 · 목록 · 인용 · 구분선 · 이미지 · 영상. 글꼴 · 자간 · 글자색은 넣지 않았습니다. 등록자마다 다르게 꾸미면 사이트 디자인이 무너집니다.

이미지는 두 종류. 대표 이미지는 16:9 고정(목록 카드 · 썸네일 · 공유용), 본문 이미지는 비율 자유입니다.

영상은 세 가지. 임베드 · 배경 루프 · 본편(9월 예정). 배경 루프는 큰 화면용 1280×720 · 작은 화면용 640×360 두 벌을 올립니다. 목록 한 화면에 큰 것 1개와 작은 것 8개가 함께 깔려서, 한 벌로 돌려쓰면 13MB가 나갑니다.

인터뷰는 인사이트 연결. 별도 데이터가 아니라 등록된 인사이트 하나를 붙이는 블록입니다.

블록마다 미리보기 버튼. 그 블록만 실제 화면 모양으로 팝업에 뜹니다. 국·영문과 PC·모바일을 전환할 수 있습니다.

연결은 루나가 미리 4개를 채워 둡니다. 사람은 빼거나 바꾸기만 하면 됩니다. 빈 상태에서 고르게 하면 아무도 안 채웁니다. 하나를 빼면 다음 후보가 자동으로 들어옵니다.

입력 가이드 — 글자 수는 실측값입니다

목업 사이트에서 각 요소의 실제 폭과 글자 크기를 재서 뽑았습니다. 국문은 한 글자가 글자 크기만큼, 영문은 절반 정도를 차지하므로 두 언어의 허용 글자 수가 두 배 차이 납니다.

주요 실측 — 목록 작은 카드 제목 428px / 36px → 국문 11자가 한 줄 · 인터뷰 인용문 412px / 28px → 국문 19자가 한 줄, 58자가 세 줄 · 관련 콘텐츠 제목 220px / 18px → 국문 12자가 한 줄, 두 줄까지 표시.

글자 수 표시가 입력칸 오른쪽 위에 항상 뜹니다. 권장을 넘으면 주황, 한계를 넘으면 빨강으로 바뀝니다. 넘어도 저장은 되지만 「공개 전 점검」에 걸립니다.

가이드가 필요 없는 칸에는 넣지 않았습니다. 연도·카테고리·공개일처럼 고를 것이 정해진 칸은 설명이 오히려 방해가 됩니다.

인사이트 · 메인 화면 · 정적 페이지 등록 화면에도 같은 방식으로 가이드를 답니다.

칸마다 「쓰이는 곳」을 적었습니다. 한 번 넣은 정보가 어디까지 쓰이는지 보이면, 왜 신경 써서 써야 하는지 알게 됩니다.

아직 안 정한 것

이미지 전체화면 뷰어 — 화면 디자인이 없습니다. 훈희 이사님 작업이 필요합니다. 좌우 화살표 · 키보드 이동 · 워크 전체 이미지 순환.

2단 2:1 배치의 작은 쪽이 세로형(0.89)으로 잡혀 있습니다. 의도인지 확인이 필요합니다.

본편 영상 호스팅 — 어느 서비스를 쓸지, 비용이 얼마인지 조사가 필요합니다.

블록 제목의 앵커 메뉴 폭은 아직 재지 못했습니다. 16자는 추정이므로 실제 메뉴가 붙은 뒤 확인이 필요합니다.

모바일 글자 수는 따로 재야 합니다. 위 숫자는 전부 데스크탑 기준입니다.
