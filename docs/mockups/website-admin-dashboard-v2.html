설계왜 이렇게 만들었나
대시보드는 「지난 30일이 어땠나」가 아니라 「지금 뭘 해야 하나」입니다

그래서 신호등이 화면 가운데에 있고, 각 줄에 「고치기」 버튼이 붙습니다. 통계를 깊게 보는 것은 「통계」 메뉴로 넘어갑니다.

트래픽 카드는 맨 위에 둡니다

매일 아침 가장 먼저 보는 숫자입니다. 각 카드 아래 30일 미니 그래프가 붙어 추세가 바로 보입니다.

그 아래 「오늘 잘 보이는 콘텐츠」를 둡니다. 국가·시간대·디바이스는 한번 파악하면 잘 안 바뀌지만, 매일 달라지는 건 「어느 콘텐츠가 반응하나」이고 그게 다음에 뭘 쓸지를 정합니다.

SEO · AEO · GEO 로 탭을 나누지 않습니다

세 이름은 업계 구분이지 우리가 일하는 단위가 아닙니다. 실제로 판단하는 건 이것입니다.

보이는 것무슨 뜻인가
노출은 많은데 클릭이 없다제목 · 설명 문제
클릭은 있는데 AI 인용이 0본문 깊이 · FAQ 문제
둘 다 0색인이 안 됐다

한 줄에 나란히 놓아야 이 판단이 됩니다. 탭으로 나누면 오히려 안 보입니다.

GA를 버리지 않습니다. 가져와서 합칩니다

GA는 데이터를 잘 모읍니다. 문제는 세 가지입니다.

  • GA 화면에 우리 콘텐츠 이름이 없습니다. /works/lotte-duty-free-star-avenue 만 보입니다. 우리는 DB에 워크가 있으니 이름으로 바꿔 보여줄 수 있습니다. GA 혼자서는 못 하는 일이고, 이 화면을 따로 만드는 가장 큰 이유입니다
  • AI 인용을 못 봅니다. 클릭이 없으면 GA에 아무것도 안 남습니다
  • 검색 노출은 GA가 아니라 Search Console에 있습니다. 두 화면을 따로 봐야 합니다

그래서 매일 새벽에 GA4 API · Search Console API로 끌어와 website_stats에 날짜별로 쌓고, 한 화면에서 봅니다.

AI 인용은 직접 재야 합니다

지금 유입으로 잡히는 것은 ChatGPT 일부와 Perplexity 일부뿐입니다. Claude · Gemini · AI Overviews는 클릭이 있어도 리퍼러가 잘 안 남거나 애초에 클릭이 없습니다.

그래서 질문 30~50개를 등록해두고 주 1회 각 AI에 던져 기록합니다. 아폴론이 나왔는지 · 몇 번째인지 · 어느 페이지를 근거로 삼았는지까지.

트렌드 레이더와 구조가 똑같습니다. 기존 파이프라인에 질문 목록만 얹으면 됩니다.

신호등에 넣는 기준은 하나 — 누르면 갈 곳이 있는가

WordPress Site Health가 늘 노란불인 이유는 고칠 수 없는 항목까지 넣기 때문입니다. 항상 노란불이면 아무도 안 봅니다.

그래서 뺀 것 — 페이지 속도 점수 · 모바일 사용성 경고 · 백링크 수. 알아도 그 자리에서 못 고칩니다.

「통과 9」를 문제 개수와 함께 보여줍니다. 문제만 보이면 항상 나쁜 사이트처럼 느껴집니다.

할 일이 없으면 신호등이 초록으로 바뀝니다

항목 목록은 접히고 「사이트가 정상입니다」 한 줄만 남습니다. 항상 떠 있으면 무시하게 됩니다.

「받은 내용」으로 묶지 않고 흩어놓습니다

예전 안은 문의 · 인재풀 · 뉴스레터를 한 덩어리로 묶었습니다. 세 가지 이유로 바꿉니다.

  • 사이트 메뉴와 이름이 같으면 헷갈리지 않습니다. 「Career 페이지 고치려면 어디 가지」가 바로 나옵니다
  • 한 메뉴 안에서 다 끝납니다. 예전엔 Career 하나 고치려고 「페이지」와 「받은 내용」 두 군데를 가야 했습니다
  • 「받은 내용」이라는 이름이 애매합니다. 문의는 답해야 하고 뉴스레터는 그냥 쌓입니다. 성격이 다릅니다
FAQ는 각 메뉴 안에 둡니다

Expertise FAQ는 회사 질문, Career FAQ는 채용 질문, Let's Talk FAQ는 문의 질문입니다. 성격이 완전히 달라 한 화면에 모으면 「이건 어디 FAQ지」를 매번 확인해야 합니다.

각 메뉴 안에 탭으로 두면 Career를 고칠 때 채용 공고와 FAQ를 같이 봅니다.
