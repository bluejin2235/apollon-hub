# 검색 오타와 자습 성과 판정 수정

## 구현

`parseAskedWhat`가 전달받은 프로젝트/고객 등록 목록을 사용해 길이 4 이상 한글 이름의 한 글자 삽입·삭제·치환을 보정한다. 첫 두 글자가 같고 후보가 정확히 하나일 때만 보정한다. 정확한 등록 이름, 숫자 포함 이름, 복수 후보, 등록되지 않은 이름은 추측하지 않는다. 원본 질문이나 회사 데이터는 수정하지 않는다.

해운대스퀀어/해운대스퀵어를 해운대스퀘어로 인식해, 오타 자체가 필수 추가 토큰으로 남아 정상 경로를 탈락시키는 현상을 막는다. 해운대의 다른 프로젝트와 견적 자료가 KV 결과에 섞이지 않는 음성 대조 시험도 포함한다. 공백·조사·모든 오타를 해결한 것은 아니다. 전체 검색 엔진의 검색어 재작성도 이번 변경은 아니다.

`runProbeRetrievalExam`의 답안 기반 시험은 오답이 발생했다는 이유만으로 improved를 반환하지 않는다. 시험을 수행했으면 no_change, 수행 건수가 0이면 failed로 기록한다. 오답 건수·원인·비용은 그대로 남는다. no_change는 기존 스키마상 '성능 개선 입증 없음'을 의미하며 '오류가 없다'는 뜻은 아니다. 이전에 저장된 잘못된 improved 기록은 아직 수정하지 않았다.

## 검증과 남은 범위

`tests/luna/search-regression.test.cjs`는 실제 파서→경로 필터와 실제 시험 조정 함수의 반환값을 검사한다. LLM·운영 DB 호출은 없다. 기존 검색 기준 스크립트의 오타 2건은 통과로 바뀌며, 아트리움 분류·부분 자료 not_found 판정·제목을 바꿔 인용한 출처 카드 문제는 아직 남는다. 이는 구성요소 회귀 결과이며 실제 직원 업무 성공률이 아니다.

운영 통합 전 실제 채팅에서 같은 질문과 잘못된 프로젝트 대조 질문을 확인해야 한다. 시험 DB/NAS 실행 준비는 company-pc-check.md를 따른다. Make는 범위에서 제외한다.
