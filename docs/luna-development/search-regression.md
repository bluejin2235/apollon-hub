# 검색·평가 회귀 수정

## 구현 범위

- `parseAskedWhat`는 전달받은 프로젝트/고객 목록에서 길이 4 이상 한글 이름의 한 글자 삽입·삭제·치환 후보를 찾는다. 첫 두 글자가 같고 후보가 하나일 때만 보정한다. 정확한 이름, 숫자 포함 이름, 복수 후보, 미등록 이름은 추측하지 않는다. 원본 질문·회사 데이터는 바꾸지 않는다.
- 해운대스퀀어/해운대스퀵어가 필수 추가 토큰으로 남아 정상 KV 경로를 탈락시키는 현상을 막는다. 다른 해운대 프로젝트와 견적 자료가 KV 결과에 섞이지 않는 대조 시험을 포함한다. 전체 검색 엔진의 검색어 재작성, 모든 조사·띄어쓰기·오타 처리는 아직 아니다.
- 아트리움은 기본적으로 공간 속성으로 취급해 미등록 프로젝트명으로 강제하지 않는다. 명시적 회사 프로젝트 등록에 같은 이름이 있으면 등록을 우선한다. 원문 검색은 유지한다.
- 자료·문서·파일을 확인/발견했다고 명시한 문장이 함께 있으면 전체 답변을 not_found로 판정하지 않는다. 실패 수집과 결과 카드 숨김에 같은 긍정 근거 판별을 사용한다. '질문은 확인했다'는 일반 응답은 제외하고 실제 자료 부재 답변은 계속 실패로 분류한다. 이는 텍스트 기반 오탐 감소이며 실제 출처 검증을 대신하지 않는다.
- `runProbeRetrievalExam`은 오답 발생만으로 improved를 반환하지 않는다. 수행 건수가 있으면 no_change, 0이면 failed를 반환한다. no_change는 기존 스키마상 '개선 입증 없음'이다. 오답 건수·원인·비용은 유지한다. 과거에 저장된 잘못된 improved 기록은 아직 수정하지 않았다.

## 검증과 한계

`tests/luna/search-regression.test.cjs`는 실제 파서→경로 필터, 시험 조정 함수, 실패 판정→카드 필터를 검사한다. LLM·운영 DB 호출은 없다.

기존 구성요소 기준 7건 중 오타 2건·아트리움·수원 부분자료 판정이 실패→통과로 바뀌고 정확 표기·다른 프로젝트 제외는 유지된다. 제목을 바꿔 인용한 출처 카드는 아직 실패한다. 구성요소 관찰 결과를 직원 업무 성공률로 해석하지 않는다.

운영 통합 전 실제 채팅에서 대표 질문과 다른 프로젝트 대조 질문을 확인해야 한다. 회사 PC에서만 필요한 확인은 company-pc-check.md를 따른다. Make는 제외한다.

## 출처 ID 연결과 회사 PC 변경 보존

후속 변경은 Notion 자료의 실제 페이지 ID를 HTML 주석 형식으로 프롬프트에 제공하고, 모델이 사용한 자료의 주석을 답변에 남기도록 한다. 실제 채팅 후처리는 답변 모델에 전달한 ID 목록과 대조해 해당 출처 카드를 유지한다. 제목이나 설명을 바꾸어도 확인된 ID가 있으면 유지하며, 임의 ID·미주입 ID·코드 블록의 예시는 인정하지 않는다. 기존 제목/URL 판정은 호환성을 위해 남는다. 주석은 출처 연결용이며 자료 내용이 답을 뒷받침하는지 증명하지 않는다. 실제 모델의 식별자 준수율과 스트리밍 화면 검증은 아직 필요하다. 기존 무인용 기준을 억지로 통과시키지 않고, 명시적 ID 인용 회귀 시험을 별도로 추가했다.

사용자가 제공한 회사 PC의 `failures-shared.ts` 미커밋 추가 기능(열린 실패 질문 그룹핑·정렬)을 함께 보존했다. 그 기능과 부분 자료 판정이 함께 동작하는 시험을 추가했다. 회사 PC 파일 자체를 수정하거나 나머지 미커밋 작업을 통합한 것은 아니다.
