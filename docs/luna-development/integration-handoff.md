# 운영 통합 전 검증 — 2026-09-25

## 자동 검증과 실제 운영 검증의 구분

- Node/PGlite: 합성 102,280건으로 실제 scanner.js의 commit 함수와 SQL RPC를 연결한다. HTTP는 가짜 전송이며 실제 NAS와 무관하다.
- `LUNA NAS PostgreSQL integration` CI: 일회용 PostgreSQL 16 서비스에서 같은 SQL migration과 합성 102,280건을 실행한다. 100행 staging RPC, 교체/응답 재시도, 중간 삽입 실패 rollback, 다른 드라이브 보존, 두 연결 간 잠금 대기와 동시 SELECT, 완료 영수증 동시 재시도를 검증한다. 컨테이너는 CI 종료 후 폐기된다. 운영 Supabase/PostgREST 지연·제한·실제 운영 스키마/인덱스 차이는 별도 검증 대상이다.
- 실제 NAS: ChatGPT 실행 환경에서 사내 UNC를 읽을 수 없다. 아래 Cursor 인계로 실제 Windows 프로세스에서 문서/이미지 각 1개를 읽을 수 있는지 확인해야 한다. 파일의 내용은 반환하지 않는다.

## 관점 검색 수정

관점으로 추가한 페이지도 최신 인덱스의 non-archived 페이지를 재확인하고 같은 페이지의 제한된 본문을 첨부한다. 관점 이름의 %, _, 역슬래시는 ILIKE 리터럴로 처리한다. 검색 함수가 used_count/last_used_at을 쓰던 동작은 제거했다. 평가·진단·재시도는 직원 사용 통계를 늘리지 않는다. 생성 관점의 used_count는 기존 build-links의 실제 운영 대화 기반 재집계에서 갱신한다. 수동 관점의 검색 시각 실시간 갱신은 더 이상 수행되지 않는다. 운영에 이미 쌓인 수치는 이번 코드 수정만으로 다시 계산되지 않는다.

## 회사 PC에 필요한 최소 인계

스캐너 PR #1의 `probe-nas-access.cjs`는 의존성이 없는 별도 읽기 전용 도구다. `.env`, scanner.js, DB, 예약 작업을 읽거나 실행하지 않는다. 명시한 루트의 접근 가능 여부와 명시한 샘플 파일의 1바이트 읽기만 확인한다. 파일 내용과 전체 경로는 결과에서 제외한다. 샘플 없이 루트만 통과한 결과는 문서/이미지 읽기 증거가 아니다.

Cursor에서 수행할 작업:

1. 기존 D:\Dev\apollon-hub 및 D:\Dev\apollon-nas-scanner의 HEAD, 파일, 미커밋 작업을 변경하지 않는다. 별도 임시 폴더에서 GitHub scanner PR #1의 최신 검토 커밋을 읽는다. 원격 다운로드가 안 되면 그 사유만 보고하며 main을 갱신하지 않는다.
2. `probe-nas-access.cjs`만 실행한다. `node scanner.js`, 배포, migration, 임베딩, 스케줄러 수정은 실행하지 않는다.
3. UNC 루트 T=\\aiw\work, P=\\aiw\partners를 지정한다. 이미 알고 있는 대표 프로젝트의 문서 1개와 이미지 1개의 드라이브 및 상대 경로를 샘플로 지정한다. 파일을 ChatGPT에 업로드하지 않는다. 실제 경로를 모르면 제한된 디렉터리 조회로 확인하되 전체 NAS 재귀 스캔은 하지 않는다.
4. 예시 명령의 샘플 경로는 실제 상대 경로로 바꾼다:

```powershell
node .\probe-nas-access.cjs --root 'T=\\aiw\work' --root 'P=\\aiw\partners' --sample 'T=프로젝트\실제문서.pdf' --sample 'T=프로젝트\실제이미지.png'
```

5. JSON 결과·프로세스 종료 코드·검증 스크립트 SHA-256·실행한 커밋을 보고한다. `.env`, 토큰, 파일 본문은 출력하지 않는다. 실패 시 성공으로 해석하지 말고 Windows 세션/드라이브 가시성 문제로 남긴다. 스케줄러를 임의 실행해서 우회하지 않는다.

이 검사는 현재 세션의 접근만 증명한다. 로그오프 시 03시 Interactive 작업 실행 여부, 실제 새 스캐너와 Supabase의 결합 실행, 운영 배포 승인은 별개다.
