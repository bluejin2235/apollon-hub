# NAS 본문 검색의 원천 버전 확인

키워드 및 벡터 본문 검색은 nas_file_text의 드라이브/경로/수정 시각/크기를 현재 nas_directory 파일과 비교한다. 추출 상태가 ok가 아니거나, 파일이 없어졌거나, 버전이 다르거나, 조회 실패·중복 추출 메타데이터·서로 다른 색인 세대가 있으면 본문을 답변에 넣지 않는다. 확인은 최대 80개 경로씩 조회하며 응답 한도에 닿으면 해당 묶음을 신뢰하지 않는다.

키워드 검색에서 현재 색인에 남은 파일은 파일명/경로로 계속 찾을 수 있다. 오래된 본문 대신 파일명을 표시한다. 다른 드라이브의 동일 상대 경로에 본문을 붙이지 않는다. 벡터 검색에서는 본문/원천 버전 확인이 된 결과만 반환한다.

이것은 현재 DB 색인과의 메타데이터 일치 확인이다. NAS 실시간 접근, 내용 해시, 추출 도중의 파일 변경, 청크별 버전 원자성을 보장하지 않는다. 원천 삭제 시 본문/관계 저장 행 자체를 삭제하는 기능도 아니다. 실제 삭제·이동 판단과 재추출 큐는 후속 과제다.

## 격리 규모 검증

`node scripts/verify-nas-snapshot-scale.cjs /path/to/scanner.js`

합성 T 90,943건/P 11,337건을 메모리 PGlite에서 실제 scanner.js의 commitDriveRecords와 실제 SQL RPC로 연결했다. HTTP 전송만 가짜 어댑터다. stage 응답 유실, commit 응답 유실, 동일 요청 재시도, 타 드라이브 보존, 90,943건 교체 중 삽입 실패의 rollback, 기존 행 ID/메타데이터 보존, 미완료 영수증 및 staging 재사용 복구를 확인했다.

2026-09-25 로컬 1회 결과: T 3,548ms, P 413ms, 실패 교체 3,081ms. **운영 성능 수치가 아니다.** 네트워크, NAS 읽기, Supabase API 제한, 실제 다중 연결/잠금 대기는 시험하지 않는다. 입력은 합성 데이터뿐이며 운영 DB, 유료 API, 회사 PC에 접근하지 않는다.

검증한 scanner.js SHA-256: `560074f21e397c058aef5a717e370a9f4a7fb30618c95f8ea3bf3bf86e0c1644`.

## 프로젝트 소속의 모호성

2026-09-25 읽기 전용 조회에서 active/confidence≥0.7인 프로젝트 소속 노션 문서는 998개이며, 20개는 복수 프로젝트 소속(최대 3개)이었다. 복수 소속이 오류라는 뜻은 아니다. 기존 코드는 마지막으로 반환된 관계를 단일 project_key로 붙였다. 이제 유일한 소속이거나 기존 선택이 실제 소속에 포함되는 경우에만 라벨을 붙이고, 복수 소속에서 근거 없는 단일 선택은 null로 둔다. 관계는 삭제하지 않는다. 모든 소속을 UI에 표시하거나 프로젝트별 문서 버전을 구분하는 기능은 아직 별도 과제다.

비용 기준: 예상 추가 비용 50달러 이상인 작업은 실행 전에 사용자에게 금액과 이유를 알린다. 본 검증은 격리 합성 데이터와 읽기 전용 조회만 사용했으며 유료 모델 호출·신규 서버 생성·운영 마이그레이션을 하지 않았다.
