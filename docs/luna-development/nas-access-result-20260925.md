# NAS 접근 검사 결과와 판정 범위 — 2026-09-25

Cursor 보고에 따르면 Windows Node v24.14.1 프로세스에서 UNC 루트 T/P 및 지정된 PPTX/PNG 샘플이 모두 UNKNOWN으로 실패했고 종료 코드는 1이었다. 탐색 대상 드라이브와 UNC 경로도 현재 세션에서 찾지 못했다. 파일 본문을 읽지 못했으며 운영 스캐너·설정·작업 스케줄러·DB는 변경하지 않았다.

검증 커밋: apollon-nas-scanner `e26e30073159b7e6837ce1567f46935de34880f2`.
보고한 probe SHA-256 `d6e1438de13c736fe4372edd5b061c46c104b1e7eee1133f7111b618ff6fc74b`는 저장소 파일을 CRLF로 체크아웃했을 때의 해시와 정확히 일치한다. 저장소 LF 바이트 해시는 `820faae98a01cd39478a6a9018cd515c94537f7a507d14aee6cbc5fed5508707`. 줄바꿈 차이이며 잘못된 스크립트라는 증거가 아니다.

## 현재 알 수 있는 것

- 이 실행 환경에서 NAS 읽기 검증은 실패했다. 파일 부재, DNS, SMB 연결, 인증, 세션 차이 중 어느 것이 원인인지는 이 결과만으로 확정할 수 없다.
- 과거 03시 예약 스캔 성공과 현재 세션 실패는 서로 다른 시점/실행 문맥의 관측이다. 이를 근거로 현재 NAS 전체 장애나 스캐너 결함을 단정하지 않는다.
- 스크립트가 보고한 UNKNOWN은 정보가 부족했다. 후속 진단 도구는 access/stat/realpath_root/realpath_sample/open/fstat/read/close 단계와 안전한 errno/syscall을 추가한다. 메시지·전체 경로·본문은 출력하지 않는다.

## 다음 접근 검증

같은 실패 환경에서 반복 실행하지 않는다. NAS가 실제로 열리는 회사 Windows 세션에서 먼저 탐색기로 UNC 루트를 확인한다. 탐색기도 실패하면 네트워크/접속 상태 확인이 선행되어야 하며, 코드를 바꾸거나 방화벽/권한/스케줄러를 자동 변경하지 않는다. 탐색기는 열리는데 Cursor 프로세스만 실패하면 동일 사용자 일반 PowerShell에서 읽기 전용 probe를 실행해 결과를 비교한다. 관리자 권한 승격이나 인증정보 복사로 우회하지 않는다.

새 probe 성공도 현재 프로세스의 샘플 1바이트 읽기만 증명한다. 전체 파일 파싱, 매일 03시 작업, 로그오프 실행, 신규 스캐너와 Supabase의 결합 실행은 별도다.
