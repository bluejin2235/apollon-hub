# 회사 PC에서 필요한 읽기 전용 확인

다음 프롬프트를 회사 PC의 Cursor에 전달한다. 개발·DB 시험은 별도로 계속 진행할 수 있다. 이 확인 전에는 운영 스캐너를 교체하지 않는다.

> LUNA NAS 스캐너 배포 준비를 위해 현재 실행 상태만 확인해 주세요. 파일 수정, git pull/reset/checkout, 패키지 설치, 스캐너 실행, 작업 스케줄러 중지·수정·재시작, DB 쓰기는 하지 마세요.
>
> 1. 실행 중인 Node 스캐너 프로세스와 작업 스케줄러 항목에서 실제 scanner.js 경로, 실행 인수, 작업 디렉터리, 실행 계정, 실행 시각, 중복 실행 여부를 확인하세요. 자격 증명이나 토큰이 인수에 있으면 출력하지 말고 가리세요.
> 2. 해당 경로가 Git 저장소인지 확인하고, 저장소 이름·브랜치·HEAD SHA·미커밋 파일 목록을 기록하세요. 미커밋 내용을 덮어쓰지 마세요. scanner.js의 SHA-256도 기록하세요.
> 3. 설정은 SCAN_DRIVES, SCAN_PATHS, SCAN_UNC_T/P, SCAN_DELAY_MS만 확인하세요. .env 전체, API 키, 서비스 키, 암호는 출력하지 마세요. UNC는 공유 루트와 실제 드라이브 대응 확인에 필요한 범위만 기록하세요.
> 4. 현재 스캐너 로그의 최근 실행에서 시작/종료 시각, 드라이브별 건수, 오류, 성공·실패 상태를 확인하세요. 새 스캔은 시작하지 마세요.
> 5. T/P 등의 드라이브가 루트 전체인지 특정 하위 폴더인지 확인하세요. 현재 로그인 계정과 스케줄러 계정이 다르면 권한이 같다고 가정하지 말고 '스케줄러 계정 실기 확인 필요'로 표시하세요.
> 6. 대표 프로젝트의 문서 하나와 이미지 하나를 읽기 전용으로 열 수 있는지 확인하세요. 내부 내용이나 전체 폴더 목록을 복사하지 말고 접근 성공/실패만 보고하세요.
>
> 결과를 '실행 파일 / 저장소 상태 / 스케줄러 / 수집 범위 / 최근 로그 / 접근 확인 / 확인 못한 항목' 표로 정리하세요. 이 단계에서는 어떤 배포나 데이터 수정도 하지 마세요.
