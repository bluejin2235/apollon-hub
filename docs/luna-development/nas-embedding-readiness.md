# Work 본문 임베딩 재개 준비

2026-09-25 읽기 전용 DB 확인: 본문 추출 성공 파일 18,263건, 청크 178,852개, embedding 비어 있지 않은 청크 0개. 미처리 content 길이 합계 170,463,278자. 문자 수는 토큰 수나 과금액이 아니다. 최근 증분 추출 로그에서도 임베딩 생성은 0이다. 회사 PC 보고의 Work Text Embed Disabled와 일치하지만, 비활성화 이유 자체는 아직 확인하지 못했다.

기존 관계는 active belongs 48,151 / same 118 / follows 7이다. 본문 벡터가 비어 있다는 사실이 모든 검색이 불가능하다는 뜻은 아니다. 경로·키워드 검색은 별도다.

## 이번 수정

- `embed-nas-chunks.ts` 기본은 읽기 전용 dry-run이며 AI API·DB 쓰기를 하지 않는다.
- 기본 미처리 500청크만 조회한다. --limit은 1~5,000, --batch는 1~100만 허용한다. 알 수 없는 인수·잘못된 숫자는 즉시 중단한다.
- 실제 처리는 --apply가 있어야 실행한다. --full은 제한을 해제하지 않는다.
- 임베딩 저장 시 조회 당시 content와 embedding IS NULL을 확인한다. 다른 작업이 처리했거나 원문이 바뀐 행을 성공 건수에 포함하지 않는다.
- DB 쓰기 실패가 있으면 작업 전체를 done으로 기록하지 않는다. 재시도는 여전히 null인 청크만 대상으로 한다.

## 재개 조건

1. 회사 PC의 현재 embed-nas-chunks.ts, 호출 bat, 환경 변수 이름, 작업 비활성화 이유를 기존 소스와 비교한다. 키 값은 출력하지 않는다.
2. dry-run으로 제한된 대상 수를 확인한다. 아직 회사 PC에서는 이 수정본을 적용하지 않았다.
3. 사용하는 임베딩 모델·차원·검색 RPC 연결·데이터 접근 범위를 확인하고, 소량 표본의 실제 토큰·비용으로 전체 예산을 산정한다. 문자 수를 토큰 수로 단정하지 않는다.
4. 소량 처리 후 대표 문서가 의미 검색에 실제로 반환되는지 확인한다. 비용과 실패율이 확인되기 전 전체 처리나 스케줄러 재활성화는 하지 않는다.

기존 bat가 인수 없이 호출하면 이제 조회만 수행한다. 스케줄러를 다시 켜는 것만으로 임베딩이 생성되지 않는다. 실행 인수 변경을 명시적으로 검토해야 한다. 동시 작업의 중복 API 비용 방지용 분산 잠금·토큰 예산 자동 차단·파일 indexed_at 갱신의 완전한 원자성은 후속 과제다.
